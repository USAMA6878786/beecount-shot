# BeeCount-Shot · 记账截图

为 [蜜蜂记账 BeeCount](https://github.com/TNT-Likely/BeeCount) 做的 LSPosed 模块：**按需截图记账** + **支出桌面小组件**。

BeeCount 原本只要检测到系统截图就自动 OCR 记账，随手截个图也会产生脏账。本模块把它改成**由你决定**——只有点控制中心那一下才记账。

## 功能

**按需截图记账**

- 平时的截图（电源键 / 三指 / 长截屏）不再触发 BeeCount 识别记账
- 点控制中心「记账截图」磁贴 → 收起面板 → 约 0.15 秒让动画走完 → 截屏 → 交给 BeeCount 识别记账
- 截屏有**三级降级**，默认走第一条：
  1. **root 直接抓帧**（`screencap`）——主路径，**不依赖按键、不依赖无障碍、跟面板状态无关**，约 0.25 秒出图
  2. 抓不到才退回「截屏服务」（无障碍）直调系统截屏
  3. 再失败才退回 root 模拟「电源键 + 音量下」
- **截图编码可加速**：原始像素自编码 JPEG，比 PNG 快约 37%（403ms → 255ms）。因不同 ROM 的通道顺序不同，需先用内置的「颜色校准」过一遍，**校准不通过就继续用 PNG**
- 屏幕上弹一句 **「截图成功 / 截图失败」**，不必进相册确认
- 磁贴副标题显示当前是否就绪
- **蜜蜂记账识别完成后自动删掉这张截图**——不管它有没有识别出账单（图已经读完了，留着只会堆积）

**支出桌面小组件**

- 今日 / 本周 / 本月支出，统计口径与 BeeCount 统计页一致
- 白底圆角、背景透明度可调；默认 2×1，横向拉长后自动变成左中右三列
- 点一下刷新数字并打开 BeeCount 的记账明细页
- 在 BeeCount 里增删改账目，小组件会在 2~3 秒内跟着更新

## 环境要求

| 项目 | 要求 |
|---|---|
| 系统 | Android 8.0（API 26）及以上 |
| 框架 | LSPosed（现代 API 101 / 102） |
| Root | **本模块必须给**；蜜蜂记账本体给了更快，不给也能用 |
| 宿主 | 蜜蜂记账 `com.tntlikely.beecount`（也支持 `.dev` 构建） |

**本模块的 root 用途**（都是纯应用层做不稳的）：

- `screencap` 直接抓帧（**主截屏路径**）
- `cmd statusbar collapse` 收起控制中心
- 删除截图（识别完成后的清理）
- 重启宿主 / 读取它的日志
- 在需要时帮你把无障碍服务打开（第二条截屏路径）

**蜜蜂记账本体也建议给 root**：它自己删图最快（在自己进程里动手，不会被系统冻结）。
只给模块不给它的话，删图会退回模块侧的后台清理任务——能用，但会慢一些。
完全不想给任何人 root 的话，截屏会退回无障碍服务，功能仍可用。

## 安装

1. 从 [Releases](../../releases) 下载 `BeecountShot-vX.Y.apk` 安装
2. LSPosed → 模块 → 启用「记账截图 (BeeCount)」，并确认**作用域里勾选了蜜蜂记账**
3. 打开一次蜜蜂记账并**允许它的 root 请求**——⚠️ 这一步容易漏：弹窗上写的是**「蜜蜂记账」请求超级用户权限**，不是本模块。然后强制停止再打开（hook 只在应用启动时注入）
4. 打开「记账截图」，按页面提示添加磁贴
5. **进一次蜜蜂记账的「智能记账」，确认截图监听是开着的**——它只在被启用过之后才监听相册

## 使用

- **记账**：拉下控制中心点磁贴 → 面板收起 → 截屏 → 弹「截图成功」 → BeeCount 识别 → 识别完成后截图被删
- **小部件**：长按桌面空白处 → 添加小部件 →「记账支出」。**只能手动加**——往桌面摆小组件是桌面应用自己的事，Android 没给任何应用这个接口，连 root 也没有
- **调透明度**：模块设置页的滑块（统一应用到所有小部件）；长按某个小部件 → 重新配置则只改它自己

## 常见问题

**点了磁贴没反应？**

先看磁贴副标题，它现在会告诉你卡在哪一步：

- **副标题纹丝不动** → 这一下压根没送到磁贴服务。Android 在应用被覆盖安装后常把磁贴"晾着"（图标还在、点了没反应、过一阵子又自己好）。把控制中心收起再拉开，或打开一次设置页（会自动请求系统重新绑定磁贴）。
- **副标题变成「正在截屏…」后停住** → 点击送到了，流程中途断了，导出日志看 `[root]` / `[screencap]` 那几行。
- **弹了「截图成功」但没记账** → 多半是蜜蜂记账的**截图监听没在跑**。它的监听只在「智能记账」里被启用过之后才注册，界面被系统回收后也可能掉。打开一次它、确认截图监听开着即可。

副标题的每次变化都会写进日志（`[tile] subtitle -> …`），所以"点了没反应"这类问题永远有据可查。

**从点击到截图被删，大概要多久？**

实测约 **10 秒**，而且**大头不在本模块**：

| 环节 | 耗时 |
|---|---|
| 截图（raw+JPEG） | 0.25 秒 |
| 蜜蜂记账发现这张图 | 数秒（它自己的观察者链路） |
| 蜜蜂记账 AI 识别 | 3~5 秒（智谱 glm-4v-flash） |
| 删图 | 识别完成后立刻 |

**改了配置不生效？**

hook 只在应用启动时注入。用设置页的「重启蜜蜂记账」（强制停止并重新打开）即可。

**截到的图里带着控制中心？**

说明这台机器收面板的动画比 0.15 秒更慢。现在截屏是 root 直接抓帧，抓的就是"那一瞬间的屏幕"，面板没退干净就会拍进去。把等待时间调大（`Const.SHOT_SETTLE_MS`）。

**连着点两次磁贴，第二次的图没被记账？**

v2.7 已修。原因是蜜蜂记账上报一张截图要延迟约 10 秒，而放行额度原本只有一份、一次性清零，第一张上报时会把第二张的额度一起吃掉。现在每次点击各发一张独立通行证。

**更新模块后磁贴点了没反应？**

这是无障碍服务的老毛病：Android 在应用被覆盖安装后会**自动关掉它的无障碍服务**。v2.19 起主路径换成 root 直接抓帧，不再依赖它，所以给了 root 就不会再遇到。

**小部件数字是灰色的？**

说明 BeeCount 进程没在跑，此时显示的是上次的数值；打开一次它就会恢复实时。

**截图什么时候会被删？**

**蜜蜂记账识别完就删**——不管有没有识别到账单。理由很简单：图已经读完了，留着只会占相册。

判定的唯一依据是**精确配对**：蜜蜂记账每处理完一张截图会写一条日志，按"闸门放行的先后"与日志一一对上，配到就删。

配不上号、日志没读到、或者这张还没出结果时一律**不删**。宁可漏删，绝不误删。

## 权限与隐私

| 能力 | 用途 |
|---|---|
| LSPosed / root | 拦截宿主截图上报；直接抓帧截屏；收起控制中心；删除截图；重启宿主 |
| 无障碍服务 | **备用截屏路径**（root 抓帧失败时才用）；不读取屏幕内容、不监听界面事件 |
| 读取照片 | **可选**。只用来判断"最新一张截图是否落盘"，以便更快确认截屏成功；不给会自动退回扫描方式 |
| 显示在其他应用上层 | **可选**。Android 12+ 会丢弃后台应用的 Toast，这个权限只是让那句「截图成功」能显示出来；不给不影响功能 |
| 网络 | **不使用**，不收集、不上传任何数据 |

模块不直接读取 BeeCount 的数据库做业务判断，而是让 BeeCount 在自己的进程里读、再通过广播把结果送回来（原因见下方技术说明）。桌面小组件除外——那个需要读库统计，是只读查询。

**关于广播通道的身份校验**：模块的几条跨进程通道用的是明文 action，接收器又必须注册成
`RECEIVER_EXPORTED`（发件人是另一个应用）。所以 v2.12 起加了发送方校验，策略是
**只做能确认时的拦截**——只在"确实查出了发件人的包名、而且一个都不是我们的人"时才拒，
取不到 uid、查不到包名等一切不确定的情况一律放行。最坏结果只是校验没生效，
不会把正常功能拦死。（用签名级自定义权限做不到：模块自己、蜜蜂记账、root 冗余通道
三者的签名身份天生不同。）

## 从源码构建

不需要 Android Studio，用 Android SDK 自带的构建工具直接出包：

```bash
# 需要 JDK 17、build-tools 35、platforms/android-35；路径在 build.sh 顶部按你的环境改
bash build.sh
```

链路：`aapt2（含生成 R.java）→ javac → d8 → 打包 dex 与 META-INF/xposed → zipalign → apksigner`，产物输出到 `release/`。

改版本号只需改 `build.sh` 顶部的 `VERSION_NAME` / `VERSION_CODE` 两行（同时同步 `xposed/module.prop`）。

⚠️ `AndroidManifest.xml` 里**不要**写 `android:versionCode` / `android:versionName`——aapt2 link 以 manifest 为准，写死会盖掉命令行传的值，表现就是"版本号一直不涨"。

**签名密钥（`beecount-shot.jks`）不在仓库里，只保留在本地**（`.gitignore` 已挡住）。

各版本签名一致，所以可以直接覆盖安装。要做到这一点，**这把密钥就不能丢**——
一旦丢失就没法再签出同签名的 APK，已装过的设备必须**卸载重装**，
而重装会连带清掉 root 授权和 LSPosed 的作用域。所以请单独备份一份。

`build.sh` 在找不到密钥时会**直接报错退出**，而不是悄悄生成一把新的——
后者会换掉签名且没有任何提示，是个很难查的坑。

## 技术说明

- **Hook 点抗混淆**：锚在 `io.flutter.plugin.common.MethodChannel.invokeMethod`、按方法名 `onScreenshotDetected` 过滤。宿主自己的 proguard 规则已 keep 该包，字符串常量也不会被混淆，因此抗升级。
- **跨进程通信一律用广播**：`su` 跑在全局挂载命名空间，看不到应用的数据目录，用 root 读写宿主私有数据会**静默失效**。所以凡是需要宿主数据的场景，一律让宿主自己读、再广播回来。
- **截屏走 `screencap` 而不是按键**：注入的按键会被正在收起的控制中心吃掉，实测约三成第一次没反应；`screencap` 是同步的，抓完就有结果，不依赖按键也不依赖无障碍。
- **raw+JPEG 需要逐机型校准**：`screencap` 不加 `-p` 出的是 RGBA 原始像素，而 `Bitmap` 的 `ARGB_8888` 在内存里是 BGRA，两种顺序**在不同 ROM 上不一样**。所以内置 `ColorProbeActivity`：画红/绿/蓝/青四块纯色再抓自己，按**已知色值**判定，错的那个差值直接 255。结果存进 `raw_swap`，未校准或校准失败时继续用 PNG。
- **删图是单工人 + 队列**：连点时不会每次点击各起一个线程（原来 10 连点就是 10 个线程并发开 root shell 扫盘）。现在只有一个工人线程，每轮只扫一次盘、同一张图只查一次宿主、宿主状态只探一次，队列空了自动退出。
- **小组件统计口径**与 BeeCount 统计页一致：`type='expense'`、`exclude_from_stats=0`、金额取 `COALESCE(native_amount, amount)`、月周期跟随账本的 `month_start_day`、周从周一起算。
- **RemoteViews 限制**：布局只能用白名单视图（`<View>` 会让桌面解析失败）；背景位图走 Binder，必须限制尺寸。

## 已知限制

**蜜蜂记账没有无界面的自动记账入口。** 实测确认过三条路都走不通：

| 尝试 | 结果 |
|---|---|
| 模块主动往它的 Flutter 通道塞「有新截图」 | Dart 侧按需注册处理器，没注册时连回执都没有 |
| 用 `ACTION_SEND` 把图分享给它 | 必然弹到前台；且它与自己的观察者重复认领 |
| 走 `beecount://` 深链 | 同样要拉起界面 |

它的截图监听（`ScreenshotMonitorService`）**只在被启用过之后才注册**，且只对 MediaStore 的 `insert`/`update` 通知有反应——root 直接写文件到相册目录**不会**触发它（实测确认）。

所以本模块的上限就是：**它启动过一次、监听在位时全自动；界面被系统回收后需要重新打开一次它。**
